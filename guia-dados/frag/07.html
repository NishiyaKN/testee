Hub: tudo vai a todas as portas, um único domínio de colisão, half-duplex. Switch: cada porta é um domínio de colisão e pode operar em full-duplex. Roteador: cada interface é uma sub-rede IP diferente.

Switch por autoaprendizado: anota “MAC de origem está na porta p”; destino conhecido → só aquela porta; destino desconhecido ou broadcast FF:FF:FF:FF:FF:FF → inunda todas as portas, menos a de origem.

Problema = colisões (CSMA/CD, recuo exponencial) e requisito = todos na mesma sub-rede/mesmo domínio de broadcast ⇒ switch. Troca hub → switch: domínios de colisão aumentam (1 por porta), portas em full-duplex, domínio de broadcast continua 1, endereçamento IP não muda.
  • Hub “Gigabit/Enterprise” continua camada 1: velocidade não separa colisões. Hubs em cascata aumentam o domínio de colisão.
  • Roteador isola colisão e broadcast: viola “mesmo domínio de broadcast” (cada interface é outra rede IP).
  • Switch não reduz ARP nem bloqueia broadcast e não põe os PCs em redes IP diferentes. O hub é camada 1, não 2.

Contagem: cada porta de switch em uso = 1 domínio de colisão; um hub inteiro com seus PCs = 1; cada interface de roteador = 1 domínio de broadcast.

Passo a passo: rede e broadcast de um IP
  1. Octeto interessante = o da máscara que não é 255 nem 0. Salto = 256 − esse valor.
  2. Rede = maior múltiplo do salto ≤ valor do octeto do IP (é o resultado do AND); octetos à direita = 0.
  3. Broadcast = rede + salto − 1 nesse octeto; octetos à direita = 255.
  4. Hosts: rede + 1 até broadcast − 1.

Ex.: 192.168.50.75/26 → salto 256 − 192 = 64; blocos .0, .64, .128, .192; 75 cai em .64–.127 ⇒ rede .64, broadcast .127, hosts .65–.126. Em binário: 75 = 0100 1011 AND 1100 0000 = 0100 0000 = 64.

Ex.: 172.16.45.130/20 → 3º octeto, salto 16; 45 cai em 32–47 ⇒ rede 172.16.32.0, broadcast 172.16.47.255, 4094 hosts.

Passo a passo: dividir um bloco
  • Por nº de sub-redes N: menor b com 2^b ≥ N; nova máscara = n + b. Ex.: 192.168.50.0/24 em 4 → b = 2 → /26: redes .0, .64, .128, .192; broadcasts .63, .127, .191, .255; 62 hosts cada.

O transmissor envia no máximo min(cwnd, rwnd); vazão ≈ cwnd/RTT. rwnd = controle de fluxo (protege o receptor); cwnd = controle de congestionamento (protege a rede).

  1. Partida lenta: cwnd começa em 1 MSS e dobra a cada RTT até o ssthresh.
  2. Prevenção de congestionamento: acima do ssthresh, +1 MSS por RTT (linear).
  3. Perda: sempre ssthresh = cwnd atual ÷ 2. Com 3 ACKs duplicados, cwnd cai à metade (recuperação rápida). Com timeout, cwnd = 1 MSS e a partida lenta recomeça.

  • Protocolo = sintaxe (formato) + semântica (significado/ação) + temporização (quando e em que velocidade). Serviço = o que a camada oferece; interface = como a de cima o acessa (send/receive); protocolo = conversa com a camada par do outro lado.
  • IP = melhor esforço: não garante entrega, ordem nem ausência de duplicatas. Princípio fim a fim: a inteligência fica nos hosts. Ampulheta: o IP é o único ponto comum entre aplicações e tecnologias físicas. No OSI o modelo veio antes dos protocolos; no TCP/IP, depois.
  • Cliente-servidor: servidor sempre ligado, endereço fixo; clientes não falam entre si. P2P: cada par é cliente e servidor ao mesmo tempo, autoescalável (BitTorrent).
  • Circuitos: reserva fim a fim, desempenho garantido, desperdício (telefonia). Pacotes: sem reserva, store-and-forward (recebe o pacote inteiro antes de reenviar), fila e perda. Multiplexação estatística: enlace de 1 Mbps, usuários de 100 kbps ativos 10% do tempo → circuitos atendem 10; pacotes, 35 (P(mais de 10 ativos) inferior a 0,0004).
  • Borda = sistemas finais; núcleo = malha de roteadores.
  • d_nodal = d_proc + d_fila + d_trans + d_prop. d_trans = L/R (não depende da distância); d_prop = d/s (não depende do tamanho). Store-and-forward: some trans + prop de cada enlace. Ex.: 1500 B; 10 Mbps/1000 km e 100 Mbps/3000 km; s = 2×10⁸ m/s → 1,2 + 5 + 0,12 + 15 = 21,32 ms.
  • Intensidade de tráfego La/R → 1: o atraso de fila explode. Vazão fim a fim = min(R₁…R_N) (gargalo). Produto banda-atraso = R·d_prop (bits “dentro do cabo”).
  • dB: 3 dB = metade, 10 dB = 1/10, 20 dB = 1/100; perdas e ganhos somam. S/N linear = 10^(dB/10).
  • Nyquist (sem ruído): C = 2B·log₂V. Shannon (com ruído): C = B·log₂(1 + S/N), teto que nenhuma modulação supera. Ex.: 3000 Hz e 30 dB → 29,9 kbps (≈ 32 níveis).

Fibra: imune a interferência eletromagnética e difícil de grampear. Sem fio: mais frequência = mais capacidade e menos alcance.
  • Topologia física (cabos) × lógica (como os dados circulam): hub = estrela física + barramento lógico. Malha completa: n(n−1)/2 enlaces (12 nós → 66). Estrela: cabo rompido isola 1 nó; centro = ponto único de falha. Barramento: um rompimento derruba tudo. Anel: token, sem colisões.
  • Porta (16 bits) = processo; IP (32/128 bits) = interface, fim a fim (não muda no caminho, sem NAT); MAC (48 bits) = placa, salto a salto. No enlace R1–R2: IP origem A, destino S; MAC origem R1, destino R2.
  • ARP: request em broadcast (“quem tem o IP X?”), reply em unicast, cache. Sem autenticação → ARP spoofing (man-in-the-middle); defesa: Dynamic ARP Inspection.
  • CRC: acrescente r zeros (r = nº de bits de G − 1), divida por XOR, anexe o resto R; no receptor, resto ≠ 0 ⇒ descarta. Ex.: D = 101110, G = 1001 → R = 011, envia 101110011. Paridade simples falha com 2 bits; paridade 2D corrige 1 bit; checksum no IP/TCP/UDP; CRC-32 no Ethernet.
  • CSMA/CD (Ethernet compartilhado): detecta colisão, envia jam, recuo exponencial K ∈ {0…2^min(n,10) − 1} × 512 tempos de bit. Quadro mínimo de 64 B para a colisão ser detectada durante o envio. Wi-Fi usa CSMA/CA: o rádio não escuta enquanto transmite e há terminal oculto; usa recuo que congela com o canal ocupado e ACK; RTS/CTS opcional.
  • VLAN (IEEE 802.1Q): cada VLAN é um domínio de broadcast separado na mesma infraestrutura; nos troncos o quadro leva tag de 4 B com VLAN ID de 12 bits. Entre VLANs só com roteador ou switch de camada 3.
  • STP (IEEE 802.1D): o quadro Ethernet não tem TTL, então um laço entre switches gera broadcast storm. O STP elege um switch raiz e bloqueia portas até formar uma árvore, reativando-as se um enlace cair.
  • Quadro Ethernet II: preâmbulo + SFD 8 | MAC destino 6 | MAC origem 6 | tipo 2 | dados 46–1500 | FCS 4. MAC: 24 bits de OUI (fabricante) + 24 do fabricante.
Switch sem VLAN inunda broadcast para todas as portas. Hub não lê tags nem MAC. TTL é do IP, não do quadro.

Agregação: 2^k redes contíguas e alinhadas = tirar k bits do prefixo. 200.10.0.0/24 a 200.10.3.0/24 (4 = 2²) → 200.10.0.0/22. Oito redes /24 → /21 (uma /22 só agrega quatro).

  • 128 bits, 8 grupos de 16 bits em hexadecimal. Abreviar: tirar zeros à esquerda; trocar uma única sequência de grupos zerados por “::” (a mais longa; empate → a primeira). 2001:db8:0:0:1:0:0:1 → 2001:db8::1:0:0:1 (nunca 2001:db8::1::1).
  • Cabeçalho fixo de 40 B, sem checksum; roteadores não fragmentam (só a origem, após descobrir a MTU do caminho); opções viram cabeçalhos de extensão.
  • Sem broadcast: usa multicast; o NDP (ICMPv6) substitui o ARP. SLAAC: prefixo /64 via Router Advertisement. EUI-64: FFFE no meio do MAC e inverte o 7º bit (00:1A:2B:3C:4D:5E → 021a:2bff:fe3c:4d5e).
  • Prefixos: 2000::/3 global; fe80::/10 link-local; fc00::/7 ULA (privado); ff00::/8 multicast; ::1 loopback.
  • Transição: pilha dupla (a mais usada), tunelamento (6in4, 6to4), tradução (NAT64/DNS64, 464XLAT).
  • Dijkstra (estado de enlace): a cada passo entra em N' o nó de menor D ainda não definitivo; atualiza D(v) = min(D(v), D(w) + c(w,v)). O(n²), ou O(|E| log n) com heap. A partir de u: x = 1, v = 2, y = 2, w = 3, z = 4 (todos via x, menos v). A partir de z: y = 2, w = 3, x = 3, u = 4 (z–y–x–u), v = 5.
  • Bellman-Ford (vetor de distâncias): D_x(y) = min_v {c(x,v) + D_v(y)}. Ex.: vizinhos v (custo 2, informa 5), w (7, informa 1), y (1, informa 8) → min{7, 8, 9} = 7 via v. Contagem ao infinito (no RIP, 16); mitigação: horizonte dividido, envenenamento reverso, hold-down.
  • Encaminhamento = local, em hardware (plano de dados); roteamento = global, em software (plano de controle).
  • Intra-AS (IGP: RIP, OSPF, IS-IS, EIGRP) busca desempenho; inter-AS (BGP-4) segue política. BGP: vetor de caminhos, TCP 179, AS-PATH evita laços. Escolha: maior local preference → menor AS-PATH → batata quente (hot potato). Não busca necessariamente o caminho mais rápido.
  • Portas (16 bits): 0–1023 bem conhecidas; 1024–49151 registradas (3306 MySQL, 3389 RDP, 5432 PostgreSQL); 49152–65535 efêmeras (lado cliente). Outras: 20/21 FTP, 22 SSH, 23 Telnet, 123 NTP, 161/162 SNMP.
  • Socket UDP = (IP destino, porta destino): consultas de origens diferentes chegam ao mesmo socket. Socket TCP = quádrupla (IP e porta de origem, IP e porta de destino): o servidor na 443 tem um socket por cliente.
  • Pare e espere: U = (L/R) ÷ (RTT + L/R). Ex.: 100 Mbps, RTT 20 ms, 1500 B → L/R = 0,12 ms, U ≈ 0,6%; janela para 100%: N ≥ (RTT + L/R) ÷ (L/R) ≈ 168 pacotes.
  • Go-Back-N: receptor só aceita em ordem (ACK cumulativo); reenvia o perdido e todos os seguintes. Repetição seletiva: guarda fora de ordem, ACK individual, reenvia só o perdido. O TCP é híbrido.
  • Seq e ACK contam bytes. ACK = próximo byte esperado (cumulativo): seq 1000 com 500 B → ACK 1500; o próximo segmento terá seq 1500.
  • Três vias: SYN (seq x) → SYN+ACK (seq y, ack x+1) → ACK (ack y+1, pode levar dados). Três, e não duas, para evitar conexão “fantasma” de SYN antigo. SYN flood (SYNs com IP falso, sem o ACK final) → defesa: SYN cookies (não guarda estado até o ACK).
  • Encerramento: FIN, ACK, FIN, ACK; quem fecha primeiro fica em TIME_WAIT (2·MSL); RST aborta. 3 ACKs duplicados → retransmissão rápida, sem esperar o timeout.
  • Timeout (RFC 6298): DevRTT = 0,75·DevRTT + 0,25·|Sample − Est| (com o Est antigo); Est = 0,875·Est + 0,125·Sample; Timeout = Est + 4·DevRTT. Ex.: Est 100, Dev 10, Sample 120 → Dev 12,5; Est 102,5; Timeout 152,5 ms. A cada timeout o intervalo dobra.

  2. ARP: MAC do gateway.
  3. DNS (UDP 53): IP do servidor.

Cada passo depende do anterior: sem IP não há DNS conhecido; sem o IP do servidor não há SYN.

  • RTTs (sem tempo de transmissão), N objetos: não persistente = 2 RTT por objeto (HTTP/1.0); persistente sem paralelismo = 1 + 1 por objeto (HTTP/1.1); persistente com paralelismo = 3 RTT. Ex.: HTML + 10 imagens → 22, 12 e 3 RTT.
  • HTTP/2: binário, multiplexado, HPACK; ainda sofre bloqueio de início de fila (HOL) no TCP. HTTP/3: QUIC sobre UDP, TLS 1.3 embutido, 1-RTT/0-RTT, fluxos independentes, migração de conexão.

MITM ataca confidencialidade e integridade; malware ataca todas; varredura de portas (nmap) é reconhecimento.

  • Simétrica: mesma chave, rápida, cifra o volume de dados (AES; DES de 56 bits e modo ECB são inseguros; GCM cifra e autentica). Problema: distribuir a chave (n pessoas → n(n−1)/2 chaves).
  • Assimétrica: par pública/privada, lenta. Confidencialidade → cifra com a pública do destinatário. Assinatura → hash cifrado com a privada do remetente. Kerckhoffs: o segredo está só na chave.
  • TLS = esquema híbrido: certificado X.509 assinado por uma AC (autentica o servidor) + Diffie-Hellman efêmero (combina a chave de sessão, sigilo futuro) + AES-GCM nos dados. TLS 1.3: handshake de 1 RTT.
  • RSA: n = p·q; z = (p−1)(q−1); e sem fator comum com z; d com e·d ≡ 1 (mod z); c = m^e mod n; m = c^d mod n. Ex.: p = 5, q = 11 → n = 55, z = 40, e = 3, d = 27; m = 8 → c = 17.
  • Diffie-Hellman: A = g^a mod p, B = g^b mod p, segredo = B^a = A^b mod p (p = 23, g = 5, a = 6, b = 15 → A = 8, B = 19, segredo 2). Sem autenticação é vulnerável a MITM.
  • Regras de cima para baixo; vale a primeira que casa; “negar tudo” por último. Sem estado = pacote a pacote (ACL). Com estado = tabela de conexões: de fora, só aceita respostas a conexões iniciadas de dentro. WAF protege aplicações web (SQL injection, XSS).
  • Ex. (Tabela 25 do Manual): SSH da TI (10.0.5.20) ao servidor web → regra 5 (as regras 1 e 3 só liberam 443 e 80/443); SSH de 10.0.7.9 → cai no “negar tudo”; RDP iniciado da Internet → não é conexão estabelecida → negado.
  • DMZ: servidores públicos entre o firewall externo e o interno. IDS detecta e alerta; IPS fica no caminho e bloqueia. Zero Trust: verificar cada acesso, menor privilégio.
  • IPsec: AH = integridade e autenticação, sem sigilo (e ruim com NAT); ESP = sigilo + integridade + autenticação; IKE negocia chaves e SAs. Modo transporte protege só a carga útil (host a host); modo túnel cifra o datagrama inteiro num novo IP (gateway a gateway, esconde endereços internos). Matriz–filial sem software nos usuários = site a site, ESP em túnel.
  • 5G (classes da UIT): eMBB = banda larga (vídeo 8K); URLLC = latência ≈ 1 ms e alta confiabilidade (cirurgia remota, veículos); mMTC = até 1 milhão de dispositivos/km² (sensores). Fatiamento de rede (network slicing) = redes virtuais distintas na mesma infraestrutura. Também: mmWave (acima de 24 GHz, pouco alcance), Massive MIMO, beamforming; no Brasil, faixa de 3,5 GHz.
  • 4G: rede totalmente IP (VoLTE), OFDMA; eNodeB, MME, HSS, S-GW/P-GW (o P-GW dá o IP e é a saída para a Internet). Reuso de frequência entre células distantes.
  • Mobilidade: handoff entre estações base; roteamento indireto (via agente nativo, “triângulo”, simples e ineficiente) × direto (eficiente, mais complexo).
  • SDN: switches só com plano de dados; controlador logicamente centralizado com visão global; aplicações via API northbound (REST); OpenFlow = API southbound. Regra = match + ação + prioridade + contadores; entre as que casam vale a de maior prioridade; nenhuma específica → regra padrão (enviar ao controlador). Ex.: (10.3.0.0/16, TCP 22) prioridade 300 = descartar vence (10.3.0.0/16) prioridade 200 = porta 4. NFV: funções de rede como software em servidores comuns.
  • Nuvem: IaaS (VMs e redes; o cliente gerencia do SO para cima), PaaS (o cliente entrega só código e dados), SaaS (aplicação pronta). Borda (edge) = processar perto da fonte (URLLC). CDN = cópias do conteúdo perto do usuário, que é direcionado por DNS ou anycast.
