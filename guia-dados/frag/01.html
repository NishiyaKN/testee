Questões reais: quiz nº 3 · slides Q3

Compara-se a taxa de crescimento quando n → ∞, e não o valor do custo para um n específico. Do mais eficiente ao menos eficiente:

Θ(1) < Θ(log n) < Θ(n) < Θ(n log n) < Θ(n²) < Θ(n³) < Θ(2ⁿ)

Regra de dominância: despreze constantes (multiplicativas e aditivas) e termos de menor ordem; fica o termo de maior grau. Formalmente, g domina f se lim f(n)/g(n) = 0.

A tabela já está em ordem crescente de taxa de crescimento.

log(nᵏ) = k·log n → Θ(log n); n·log(nᵏ) → Θ(n log n); Σ i → Θ(n²); 2ⁿ + qualquer polinômio (até n¹⁰⁰) → Θ(2ⁿ).
Ordens erradas típicas: pôr n log n antes de n (impressionado pelo 100 de 100n); pôr n antes de log₂(n⁵) (lendo como se fosse n⁵); pôr n² antes de n·log₂(n³) (lendo como n·n³ ou "cúbica"; é só 3n log n).
Para n pequeno a ordem dos valores muda por causa das constantes: n(n + 1)/2 só passa 100n + 15 a partir de n = 200, e 3n log₂ n só passa 100n + 15 perto de n ≈ 10¹⁰. A questão pede a classe assintótica, não o valor.

Teste do limite (L = lim f(n)/g(n), com n → ∞):

  • L = 0 → f = O(g), e g domina f;
  • L = constante > 0 → f = Θ(g);
  • L = ∞ → f ≠ O(g): nenhuma constante c serve, e f domina g.
Exemplo do material: n² × n log₂ n

Para n² = O(n log₂ n) seria preciso n² ≤ c·n log₂ n, isto é, n ≤ c·log₂ n para todo n grande. Mas lim n²/(n log₂ n) = lim n/log₂ n = ∞. Logo:

  • n² = O(n log n) é falso. "n log n domina n²" e "n² ≤ c·n log n para n grande" também são falsos: invertem a dominância.
  • n log n = O(n²) é verdadeiro, porque lim (log n)/n = 0: n² domina n log n.
Asserção-razão: julgue I e II separadamente; só se as duas forem verdadeiras pergunte se II explica I. Em "I. n² = O(n log₂ n) PORQUE II. n log₂ n domina n²", as duas são falsas. Na versão invertida (I. n log n = O(n²) PORQUE II. n² domina n log n), as duas são verdadeiras e II justifica I.
"I verdadeira e II falsa" atrai quem percebe o erro de II mas aceita I por intuição. A dominância correta (n² domina n log n) prova justamente que I é falsa.

Questões reais: quiz nº 2 · slides Q2

O Modelo de Knuth dá o custo exato: cada linha i tem custo cᵢ e frequência tᵢ (quantas vezes executa), e T(n) = Σ cᵢ·tᵢ. A sentinela grava a chave em v[n − 1]: o laço nunca passa do fim, então some o teste de limite (i < n) e sobra uma comparação por volta.

v[n - 1] = chave;        // Linha 1
while (v[i] != chave)    // Linha 2
    i++;                 // Linha 3
if (i < n - 1)           // Linha 4
    return i;            // Linha 5
return -1;               // Linha 6
LinhaPior caso (chave ausente)Melhor caso (chave em v[0])
1 sentinela11

  • Pior: T(n) = c₁ + n·c₂ + (n − 1)·c₃ + c₄ + c₆ → termo de 1º grau → Θ(n).
  • Melhor: T(n) = c₁ + c₂ + c₄ + c₅ → constante → Θ(1).
O teste de um laço roda uma vez a mais que o corpo: n testes e n − 1 incrementos. "Pior caso Θ(n)" e "melhor caso Θ(1)" são verdadeiros ao mesmo tempo (são cenários diferentes).
Erros de contagem: teste do while n − 1 ou n + 1 vezes (com sentinela são exatamente n); i++ n vezes (são n − 1); somar c₅ no pior caso (lá a saída é o return −1, c₆); achar que busca sequencial é "sempre linear" (o melhor caso é Θ(1)).
"Linha 2" segue a numeração dos comentários (Linhas 1 a 6), não a numeração lateral do código no slide.

Exige vetor ordenado com acesso por índice. Cada comparação com o elemento do meio descarta metade: n → n/2 → n/4 → … → 1. Pior caso ≈ log₂ n comparações, Θ(log n). A busca linear faz n no pior caso.

2¹⁰ ≈ mil, 2²⁰ ≈ 1 milhão, 2³⁰ ≈ 1 bilhão: log₂ n é o expoente. Para 1.000.000, log₂ n ≈ 19,9 → 20.

Questões reais: quiz nº 4 · slides Q4

for (int i = n; i > 0; i /= 2)
    for (int j = 0; j < i; j++)
        count++;

Com n potência de 2, i vale n, n/2, n/4, …, 2, 1 (log₂ n + 1 valores), e o laço interno roda i vezes. O total é uma PG com a₁ = n, q = 1/2 e log₂ n + 1 termos:

S = n + n/2 + … + 1 = n·(1 − (1/2)^(log₂ n + 1)) / (1 − 1/2) = 2n·(1 − 1/(2n)) = 2n − 1 → Θ(n). Ex.: n = 16 → 31; n = 1.024 → 2.047.

Aninhado não quer dizer n log n nem n²: some o que o laço interno realmente executa. Escopo dividido por 2 a cada volta → 2n − 1 = Θ(n).
n log₂ n supõe que o interno roda sempre n vezes (log n voltas × n); n(n + 1)/2 é o laço triangular, com i crescendo de 1 em 1 (a "intuição quadrática"); 2ⁿ − 1 exigiria n termos dobrando, mas aqui há só log₂ n + 1 termos, cada um ≤ n.

Alfa (4 chamadas, combinação linear) e Beta (2 chamadas, combinação quadrática) dão as duas Θ(n²): assintoticamente equivalentes, escolha indiferente do ponto de vista assintótico (conclusão do manual).

Nenhuma ordenação por comparação fica abaixo de n log n no pior caso.

Top-k com Min-Heap de tamanho k (k ≪ n)
  1. Monte um Min-Heap com os k primeiros itens: Θ(k).
  2. Para cada novo x, compare com a raiz (o menor dos k maiores): Θ(1). Se x > raiz, troque a raiz por x e rode heapify: Θ(log k).

Total: Θ(n log k) de tempo e Θ(k) de memória. É Min-Heap porque a raiz é quem sai quando chega alguém maior.

AbordagemTempoMemória

Hash com encadeamento: Θ(1) em média; se todas as chaves colidirem, a tabela vira uma lista encadeada e a busca cai para Θ(n), quebrando a previsibilidade de latência.

"Heapsort ordena em O(n)" é falso: ele é Θ(n log n) em todos os casos. É in-place, mas uma solução que guarda as n chaves num hash e as copia para um vetor usa Θ(n) de memória, e ordenar tudo para pegar k itens perde para o Min-Heap (n log k).
O slide diz que o Quicksort usa memória "Θ(1) in-place"; o correto (manual) é pilha de recursão Θ(log n), chegando a Θ(n) sem otimização.

Provar Θ exige mostrar c₁, c₂ e n₀. Exemplo: f(n) = 3n² + 10n.

  • Θ(n²) com c₁ = 3, c₂ = 4, n₀ = 10: 3n² ≤ 3n² + 10n sempre, e 3n² + 10n ≤ 4n² ⇔ n ≥ 10 (em n = 9 falha: 333 > 324).
  • Ω(n) (c = 1, n₀ = 1) é verdadeiro, mas não é firme: f/n = 3n + 10 → ∞, logo f ≠ O(n).
A dominância é pelo maior grau, nunca pelo maior coeficiente: 10n não domina 3n².
  • Pior caso: limite superior para qualquer entrada de tamanho n; é a garantia para SLA e tempo real.
  • Melhor caso: cenário mais favorável; serve para validar fast-paths e não garante nada.
  • Caso médio: média sob uma distribuição (comumente uniforme); reflete o uso cotidiano. Busca linear com chave equiprovável: (n + 1)/2 comparações, ainda Θ(n).

O interno roda i vezes: 1 + 2 + … + n = n(n + 1)/2 = 0,5n² + 0,5n → Θ(n²). n = 10 → 55; n = 1.000 → 500.500. Com j < i (até i − 1): n(n − 1)/2 = 499.500 para n = 1.000, também Θ(n²).

"n × n = n² execuções" acerta a classe mas erra a contagem; "metade em média" dá n·n/2, que continua quadrático (não gera log); 2n − 1 é do laço com i /= 2.

Merge Sort: T(n) = 2T(n/2) + Θ(n). a = 2, b = 2, fronteira n^(log₂ 2) = n. f(n) = Θ(n) é equivalente à fronteira → Caso 2 → Θ(n log n) (log₂ n níveis de recursão, Θ(n) de trabalho por nível).

Erros típicos: esquecer o fator log (responder Θ(n)); usar a fronteira n² (é a de a = 4, como na Estratégia Alfa); confundir o expoente log_b a com "log n" e aplicar o Caso 3.

Melhor caso e "mais rápido na prática" não são garantia de pior caso.

Na ABP, esquerda < raiz ≤ direita. Busca, inserção e remoção custam proporcional à altura: Θ(log n) em média. Inserir em ordem crescente ou decrescente sem balanceamento (AVL, Red-Black) gera uma "linha" de altura n → Θ(n), igual a uma lista encadeada.

"Em-ordem dá ordem crescente" é verdade, mas não explica a degeneração (a causa é a ordem de inserção sem balanceamento). 40 30 50 25 35 45 60 é o percurso por níveis, não a pré-ordem. Reinserir na em-ordem recria a árvore degenerada.

h(k) leva a chave a um índice de um vetor de m posições; fator de carga α = n/m. Boa função + α estável → busca e inserção Θ(1) em média.
